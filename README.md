# Jev Resume Filler

Chrome 简历自动填写扩展。使用本地结构化简历和附件，结合 TypeSafe Jev 的语义判断与页面执行能力，尽可能补齐招聘网站中可对应的字段。填写结果通过页面回读检查，最终核对与投递由用户完成。

## 核心能力

- 使用个人、教育、实习、工作、项目、奖项、论文、专利、语言、家庭成员等资料填写表单。
- 处理输入框、下拉、搜索选择器、日期、协议勾选、附件上传和 iframe 表单。
- 识别重复经历及其新增方式：页面内追加、弹窗／抽屉编辑、独立编辑页。
- 默认保留已有值，将缺少资料、值冲突和执行失败记录为待补项。

各网站的覆盖程度取决于页面结构和控件行为；填写结束后仍需人工核对。

## 技术框架

默认策略按“观察 → 区域任务 → 局部决策 → 执行回读”分层。网页当下的状态决定操作顺序。

```text
┌────────────────────────────────────────────────┐
│ 本地资料与扩展弹窗                             │
│ 简历 JSON、头像、生活照、附件、API Key         │
└────────────────────────┬───────────────────────┘
                         ▼
┌────────────────────────────────────────────────┐
│ 页面观察 · content.js                          │
│ 节点层级、分区、记录、字段及各自的稳定身份     │
│ 已有值、弹层、编辑器、校验提示                 │
│ 平台驱动 · platform-drivers.js                 │
│ 北森 / 飞书 / Moka 的页面与控件差异            │
└────────────────────────┬───────────────────────┘
                         │ 页面快照
                         ▼
┌────────────────────────────────────────────────┐
│ 区域任务调度 · goal-runner.js / goal-state.js   │
│ 区域 → JSON 资料块 → 当前记录 → 空字段        │
│ 观察前置开关、编辑入口及新增后的字段变化       │
│ 任务账本记录已检查、待补与受阻原因             │
└────────────────────────┬───────────────────────┘
                         ▼
┌────────────────────────────────────────────────┐
│ 动作规划 · observed-interaction.js             │
│ 语义选择 · jev-client.js                       │
│ 代码生成有限候选，Jev 进行语义选择             │
│ 分区 / JSON 资料块 / 字段绑定 / 下一动作       │
│ 明确操作交给执行器，随后回读验收               │
└────────────────────────┬───────────────────────┘
                         ▼
┌────────────────────────────────────────────────┐
│ 页面执行与回读 · page-executor.js / 控件驱动   │
│ 打开、输入、选择、日期、上传、保存、返回       │
│ 检查回显值、校验提示与记录变化                 │
│ 权限与状态 · action-policy / traversal-state  │
│ 字段身份、弹层归属、操作预算与回读状态         │
└────────────────────────┬───────────────────────┘
                         │ 新快照继续观察与规划
                         └─────────────────────↺
```

Jev 从程序提供的有限候选中选择区域、资料块与来源记录，新增前确认记录适用于当前编辑类型，再确定互斥页签并处理空字段；已有草稿保持当前类型。同一区域逐个判断空字段需要的资料块，例如个人信息中的最高学历来自教育资料。重复经历按记录处理，复合问答限定当前问题；长文本汇总可使用相关资料块的全部记录。字段决策携带本区域已填值与当前字段的弹层，其他分区保持隔离。

页面层级由 DOM 容器与打开入口的交互变化建立：分区标题用于语义判断，同名模块通过节点身份区分；起止日期与记录里的其他字段共享归属。点击新增或编辑后，调度器确认内联记录、弹窗、iframe 或独立页中出现了对应字段，再进入字段填写。当前记录填完后，继续对照所选 JSON 的记录清单检查缺少的经历；入口未成功打开会记录原因与有界尝试结果。

JSON 上下文随层级变化：外层提供简洁资料块目录，相同数组字段合并展示；选中资料块后提供完整文字；字段选择聚焦当前记录的全部字段及本分区已填内容。完整资料在请求中存放一次，候选通过索引引用；长描述、自定义字段保留完整，附件只提供元信息。失败请求记录阶段和大小，便于区分上下文限制、服务故障与控件执行问题。

无明确语义的显示槽先展开观察选项，再绑定来源。来源绑定后，单一输入、附件、精确选项及可确定的日历步骤由代码执行；语义有歧义时继续交给 Jev。每次操作重新观察，分别记录填写回读和保存证据。资料缺失、执行失败、前置条件与观察缺口作为待核对项保留。

字段绑定或选项选择置信不足时，增加一次有界核验。独立属性要求对应事实，合并描述框可采用相关的已有事实汇总，缺少的年限等属性保持省略。选项分别判断“可用导航候选”和“最终值等价”；地理父级按包含关系判断。原始选择分数与核验概率独立记录，页面变化与最终回读完成验收。

已有记录先核对身份：唯一名称及一致日期可直接确认，其他情况由 Jev 对照当前网页记录文字和所选资料块核验。明确属于其他经历的记录保持原状；归属不明时列为待核对。搜索输入保持查找层焦点，搜索确认限定在当前查找层内；并列选择器提供各自槽位及邻居值。

分区采用本轮单向终结：当前分区完成填写、保存回读或汇总待核对项后，从后续候选中移除。保存修正集中在当前分区内；末尾复核只读，后续刷新清空的字段与尚未满足的前置条件留在报告中。用户重新启动填写时建立新的分区清单。

### 默认策略：通用观察

“设置 → 字段填写策略”默认使用通用观察策略，外层区域调度与内层字段事务均采用新链路。按现阶段对照测试需求，原适配策略及北森、Moka、飞书驱动继续保留；原适配策略使用原分区调度器。两条策略共享资料格式、页面观察与执行工具。已有策略选择继续生效。

通用观察策略在当前记录内依次处理：

```text
观察控件与已有值 → Jev 选择空字段 → 选择当前 JSON 记录的来源字段
       ↑                                      ↓
重新观察并回读 ← 打开 / 输入 / 选择 / 滚动 / 等待 / 返回
```

页面观察以物理模块划定边界，分别提供真实值、搜索文字、占位符、帮助说明及校验错误。选择器先观察选项，再绑定资料来源，弹层绑定到当前字段。普通搜索由选中回执验收，自由输入由明确控件模式与站内成功校验证据验收；树节点分别提供展开开关与可选值槽，达到资料要求的精度时选择值槽，存在下级仍可选中当前节点。长选项列表通过有限窗口依次检查。Jev 可选择单项事实、重复经历或多条资料汇总；代码组合完整日期范围及带时间、等级的汇总文本，并保留来源。日期沿用已验证的控件事务或实际日历导航，以根字段回读验收。相同局部状态的操作设有重试预算，上传超时保留待核对并继续其他字段。日志分别标记观察覆盖、候选覆盖、判断、填写回读和保存结果。

真实网站覆盖程度逐项验收。新增入口、前置必填条件或控件尚未完成回读时，日志会保留原因；运行结束表示本轮检查结束，结果仍需用户核对。

## Instructions：快速配置

### 1. 安装与加载

克隆仓库，或在 GitHub 下载 ZIP 后解压：

```bash
git clone https://github.com/Mr-Banan0/Jev-Resume-Filler-Chinese.git jev-resume-filler
```

在 Chrome 打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的项目根目录。扩展源码可直接加载，无需构建。

更新代码后，在扩展详情页点击“重新加载”，再刷新招聘网站页面。

### 2. 配置 Jev 与简历

1. 点击工具栏中的扩展图标，进入“设置”，选择 TypeSafe 或 QuickRouter，填写该服务的 API Key，点击“测试连接”后“保存 API 配置”。QuickRouter 使用 `jev-1.13.0` 和 `/v1/systemone` 原生判断端点。
2. 在弹窗录入资料，或通过“设置 → 导入 JSON”导入结构化简历。
3. 选择头像、生活照和简历附件，点击“保存简历”，核对已保存的附件状态。

JSON 字段模板见 [data/resume-default.json](data/resume-default.json)，完整定义见 [data/resume-schema.json](data/resume-schema.json)，填写示例见 [data/resume-example.json](data/resume-example.json)。

### 3. 让 Agent 初始化 JSON

将简历文件、字段模板和 Schema 一并交给支持文件读取与修改的 Agent，使用以下提示词：

```text
请将我的简历转换为符合 resume-schema.json 的严格 JSON，
以 resume-default.json 为模板，保留全部字段和数组结构。

仅填写简历中明确提供或经我确认的信息。
对未提供、含糊或相互冲突的信息，主动分组向我确认；
我确认跳过的字段使用空字符串或空数组。

教育、实习、工作、项目、奖项等每段经历分别建立数组记录。
完整日期使用 YYYY-MM-DD，只有年月时保留 YYYY-MM，
“至今”保留原样；网站要求具体日或替代结束日期时，向我确认约定。
描述按要点分行，JSON 字符串使用 \n 表示换行。

确认完成后，将严格 JSON 保存为 resume-parsed.json。
```

生成后通过“设置 → 导入 JSON”导入。真实简历也可保存为 `*.local.json`；这些文件名已配置在 `.gitignore` 中。

### 4. 使用

1. 登录目标招聘网站，进入可编辑的简历页面。
2. 打开扩展，核对简历和附件状态。
3. 阅读网站协议；需要插件勾选时，在扩展中确认本次授权。
4. 点击“开始自动填写”，查看日志和待补项；需要中断时点击“停止填写”。
5. 检查页面已有值、日期、重复经历及附件，补齐待补项后自行投递。

## 数据与使用边界

- API Key、简历和附件保存在 Chrome 扩展的本地存储中。
- Jev 判断请求会向设置中选择的 API 服务（TypeSafe 或 QuickRouter）发送候选动作和相关资料。外层路由提供字段目录，资料块内的记录选择提供该块完整文字；字段决策携带当前记录全部字段、本区域已填值与当前字段的弹层。这些文字可能包含联系方式、证件号码和地址，请按接受的隐私范围配置资料。连接测试仅发送固定合成样例。
- 附件字节用于上传招聘网站，发送给 Jev 的判断请求会剔除附件字节。
- 最终提交与投递由用户操作；已有字段默认保留，冲突、缺少资料或无法执行的字段列入待补项。
- `.gitignore` 排除 `resume-parsed.json`、`*.local.json`、`data/photos/` 等本地资料；其他文件名的个人文件需加入忽略规则。

## 开发验证

```bash
cd jev-resume-filler
npm install
npm test
```

离线回归包含分区路由、重复记录、动态控件、跨帧编辑、保存失败和有界退出。真实 Jev 判断可运行 `npm run test:jev-live`，使用 `TYPESAFE_API_KEY`；测试只发送合成资料。DOM 回归与真实判断均通过后，仍需在目标网站核对实际回显和保存结果。

通用观察策略：`npm run test:observed` 执行离线回归，`npm run test:observed:live` 使用真实 Jev 完成合成表单；加 `-- --adapted` 可对照原适配策略。真实判断使用 API 额度。运行 `npm run fixture` 后，可在 Chrome 打开 `http://127.0.0.1:8765/observed-form.html`，使用合成资料测试扩展。合成表单结果仅用于验证测试场景。
